# 端末貸出管理システム システム調査および改善提案レポート

本レポートは、1台のChromebook（Linux Mint OS）上のローカル環境で動作する「端末貸出管理システム」について、ソースコードの精査および一時的なモック環境を用いた実動作確認に基づき、システムの問題点・構造的課題・改善提案を網羅的に取りまとめたものです。

---

## 1. 総評

本システムは、「ローカルSQLiteを正データとし、ネットワーク断や外部連携不調時も12扉の貸出・返却・施錠を止めない」というフェイルセーフ設計が極めて堅牢に実装されています。単一Chromebookによるキオスク端末運用という大前提に即したセキュアなローカルバインド（`127.0.0.1`限定待ち受け）、CSRF防御（`Sec-Fetch-Site`検証）、認証トークン管理、バックアップ保護など、全体的に高い完成度を有しています。

一方で、直近行われた変更（返却チェックリストの改善）において、**画面表記とプログラムロジックが真逆に解釈される深刻なロジック不整合（バグ）**が混入していることが判明しました。また、1ファイルに数千行が集中する単一肥大化構造、GAS（Google Apps Script）との全体スナップショット同期による将来的な通信負荷、運用者（専門知識を持たない教職員）が異常発生時に自力復旧しにくい点などが課題として挙げられます。

さらに、生徒向け画面（`index.html`）および管理者画面（`admin.html`）において、生年月日プレースホルダーの表記矛盾、共有キオスクでの生メールアドレス表示、返却完了ボタン表示前の説明不足、ダイアログオプションの無視 (`showCustomConfirm`)、無操作スクロール未検知、ログアウト確認の欠落など、合計21箇所のUI/UX・ロジック・セキュリティ・運用上の不備を特定しました。

### 最も深刻な問題トップ5
1. **返却チェックリスト「破損なし/あり」の判定ロジック反転バグ**（`index.html:637` / `js/app.js:2206`）
   画面には「破損はありませんか？」と表示されているのに対し、コード上はチェックボックスがオン（`true`）の時に「破損あり」と判定されるため、生徒が「破損なし」のつもりでチェックを入れると破損報告画面が開いてしまう。
2. **ローカル返却時の破損報告に対する管理者即時通知の漏れ**（`local-db/lending.js:929` / `gas/Code.gs:3158`）
   ローカルDBで返却・破損処理を行った際、故障テーブルへの記録は行われるが、GAS側の即時通知メール送信関数が呼び出されず、メール通知を有効にしていても管理者に通知が届かない。
3. **ウェルカムダイアログ/チュートリアル非表示化に伴うデッドコードの残存**（`js/app.js:2842` / `css/pages.css:4443`）
   ダイアログ呼び出しはコメントアウトされ不要となったものの、関数の定義（56行）やCSSアニメーション定義（120行以上）がデッドコードとしてそのまま残存している。
4. **`showCustomConfirm()` の `okLabel` オプション無視バグ**（`js/ui.js:520` / `js/app.js:2350`）
   呼び出し側で `{ okLabel: '端末を確認して記録する' }` を指定しているにもかかわらず、`ui.js` 側の関数定義が第3引数を受け取らず常に「OK」と固定表示される。
5. **無操作タイムアウト判定におけるスクロールイベントの漏れ**（`js/app.js:2760`）
   アイドル検知イベントに `scroll` が含まれていないため、生徒が返却一覧をスクロールだけして閲覧していると無操作とみなされ突然タイムアウトでトップに戻される。

### 現システムの最大の課題トップ3
1. **モノリシックな巨大ファイル構造**（`server.js` 約3650行、`js/app.js` 約2900行）
   機能追加やバグ修正時に副作用が発生しやすく、保守性・テスト容易性を低下させている。
2. **全体スナップショット送信方式による同期オーバーヘッド**
   履歴件数が増加するにつれてGASへのPOSTボディが肥大化し、タイムアウトや帯域圧迫のリスクが高まる。
3. **非専門家（教職員）向けの障害自己診断・ガイドUIの不足**
   ネットワーク断・USB切断・停電復旧時に、管理画面を見ても具体的な復旧手順が指示されず、手動操作のハードルが高い。

### 最も効果の高い改善提案トップ3
1. **【クイックウィン】返却チェックリストの選択UIおよび判定ロジックの修正**
   直近のバグを即座に修正し、「破損なし」「破損あり」を明示的な2択ラジオボタンに刷新する。
2. **【クイックウィン】全21箇所のUI/UX・フロントエンド改善コードの適用**
   生年月日入力プレースホルダー、空状態フォールバック、生メールアドレスのマスク、`okLabel` 対応、スクロール検知などを一括改善する。
3. **【中期改善】サーバー側・フロント側の機能別モジュール分割（リファクタリング）**
   ルーティング・ビジネスロジック・シリアル通信・同期処理を責務ごとに分離し、保守性を劇的に向上させる。

2. **返却チェックリストの「端末に破損はありませんか」の項目が、初期状態でチェック済みになっていたのを、未選択に変更した。**
   - **検証結果**: **問題あり（重大なロジック反転バグ）**
   - **詳細**: 初期状態で未選択（`_chkState[3] = false`）になるように変更されていますが、`index.html` (637行) のタイトルが「端末に破損はありませんか？（破損がある場合はチェックを外してください）」となっているのに対し、`js/app.js` (2206行) の判定コードは `const hasDamage = _chkState[3];` となっており、**「チェックが入っている＝破損あり」** と扱われます。このため、生徒が「破損なし」を意図してチェックを入れると破損報告アラートが表示され、逆にチェックを入れない（未選択の）まま他の2項目をチェックすると「破損なし」として返却できてしまいます。

3. **破損がある場合は、ログアウト画面の確認などの他のチェックを省略して、返却できるようにした。**
   - **検証結果**: **問題なし（一部通知漏れあり）**
   - **詳細**: 破損を選択して返却を進める場合、ログアウトチェック（項目1）およびシャットダウンチェック（項目2）が正しく省略され、即座に扉解錠・返却フローへ進めることを確認しました。

## 4. 問題点の詳細

### No.1: 返却チェックリストの判定ロジック反転バグ
- **該当箇所**: `index.html` 637-638行目、`js/app.js` 2206-2207行目
- **何が問題か**: UIのテキストは「端末に破損はありませんか？（破損がある場合はチェックを外す）」となっているが、JavaScriptコードでは `_chkState[3] === true` を `hasDamage = true`（破損あり）として判定している。
- **再現手順と影響**: 生徒が「破損なし」を確認してチェックを入れると「端末の損傷を報告してください」という警告が開いてしまう。
- **推奨する修正案**:
  ```javascript
  // js/app.js 修正案
  const noDamageChecked = _chkState[3];
  const hasDamage = !_chkState[3]; // 未チェック状態を破損ありとして処理
  ```

### No.3: `showCustomConfirm()` が `okLabel` オプションを無視するバグ
- **該当箇所**: `js/ui.js` 520行目、`js/app.js` 2350行目
  ```javascript
  // js/app.js 側の呼び出し
  const ok = await showCustomConfirm('確認', '端末を実際に棚へ戻したことを確認しましたか？', { okLabel: '端末を確認して記録する' });

  // js/ui.js 側の不備のある定義
  function showCustomConfirm(title, message) { // 第3引数 options を受け取っていない！
    ...
    okBtn.textContent = 'OK'; // 常に 'OK' と表示される
  }
  ```
- **何が問題か**: ボタンに具体的な説明文（「端末を確認して記録する」など）を指定して呼び出しているのに、UI上は常に一言「OK」としか表示されず、ユーザーがどの選択肢を押しているのか分かりにくい。
- **推奨する修正案**:
  ```javascript
  // js/ui.js 修正案
  function showCustomConfirm(title, message, options) {
    const opts = options || {};
    ...
    okBtn.textContent = opts.okLabel || 'OK';
    cancelBtn.textContent = opts.cancelLabel || 'キャンセル';
  }
  ```

### No.4: 無操作タイムアウト判定におけるスクロール未検知問題
- **該当箇所**: `js/app.js` 2760-2775行目
  ```javascript
  ['mousedown', 'touchstart', 'keydown', 'input'].forEach(evt => {
    window.addEventListener(evt, resetIdleTimer, { passive: true });
  });
  ```
- **何が問題か**: イベントリスナーに `scroll` が含まれていないため、生徒が返却対象者一覧画面でリストをタッチスクロール操作している間、無操作とみなされてタイマーがカウントダウンを続け、突然画面がトップへリセットされてしまう。
- **推奨する修正案**:
  ```javascript
  ['mousedown', 'touchstart', 'keydown', 'input', 'scroll'].forEach(evt => {
    window.addEventListener(evt, resetIdleTimer, { passive: true });
  });
  ```

## 5. システム全体の課題（現状分析）

### 1. 運用面の課題
- **専門知識を持たない教職員の負担**: 端末の追加・廃棄、卒業生の削除、年度替わりの一括処理を行う際、管理画面の操作が分散しており間違いやすい。
- **障害発生時の復旧の難しさ**: Arduino切断やNTP時刻未同期などの警告バナーが表示されても、具体的な復旧手順（USBケーブルの挿し直しや `dialout` 権限のコマンド等）が画面上に表示されず、教職員が自力で解決できない。

### 2. データ管理・プライバシーの課題
- **個人情報の保持とログ**: 生徒の氏名・メールアドレス・生年月日がローカルSQLite、ログファイル（`server.jsonl` / `audit.jsonl`）、および録画メタデータに保存されている。
- **スプレッドシートへの同期範囲**: 閲覧用ミラーとして氏名・メールアドレスが全件送信されている。閲覧権限の適切な制限が必要である。

### 3. 信頼性・耐障害性の課題
- **単一障害点 (SPOF)**: Chromebook本体、USBケーブル、Arduino基板、電源が単一障害点となる。ただし、ネットワーク断やGAS障害時にはローカル完結で貸出・返却を継続できる優れた耐障害性を備えている。

### 4. 設計・保守性の課題
- **ファイル肥大化**: `server.js`（3650行以上）、`js/app.js`（2900行以上）にルーティング、データ操作、画面制御、カメラ処理、タイマー管理が混在している。
